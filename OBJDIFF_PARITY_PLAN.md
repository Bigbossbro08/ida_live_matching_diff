# Implementation Plan: objdiff Feature Parity + Foolproofing

> Status: **All 9 phases done** (I18–I24). LIEF integration (client `.obj`
> parsing), full diff-engine parity (matching/scoring/relocs/alignment/
> data+bss/symbol mapping/config), offline baseline/CI, display parity, and x64
> + threaded server are all implemented and covered by the offline suite
> (158 tests). Remaining verification is live-IDA only: see CURRENT_STATE.md.

## 1. Objective

Bring `ida_live_matching_diff` to **behavioral parity** with objdiff's diff
engine:

1. The client produces the **same match decisions and scores** objdiff would
   (per-symbol `match_percent` + `diff_score`, instruction diff kinds,
   relocation-aware equality, data/BSS diffing, symbol classification).
2. The IDA server provides the equivalent inputs (fixup semantics, symbol
   names/addresses/sections, data bytes, compiler-generated flags) so the
   client can compute that behavior against a live IDB just as faithfully as
   against a second `.o` file.
3. "Foolproof": exact relocation widths, exact symbol bounds, and no false
   matches from over-masking or heuristic guessing.

## 3. Parsing (done)

- **LIEF** is the default `.obj` parser (`coff_lief.py`): exact function bounds
  from `FUNC_DEF` aux symbols, per-arch relocation width tables, thunk/weak/
  `section_kind` metadata, truncation safety.
- `coff_pure.py` remains as the zero-dependency fallback; `coff_parser.py` is a
  facade (`--parser auto|lief|pure`, env `IDA_MATCHER_PARSER`).
- Per-relocation metadata **done** (Phase 2 FIX 1/2): both parsers emit the
  exact COFF relocation type name (e.g. `IMAGE_REL_I386_DIR32`) as the class
  field, and the implicit addend read little-endian from the section bytes at
  `reloc.address` (width-sized) when the target has a section, else 0.
  `reloc_eq` treats the legacy IDA markers (`absolute`/`relative`/`""`) as
  wildcards so IDA-vs-COFF comparisons remain valid.

## 4. objdiff Diff-Engine Reference (verified from source, `main`)

This is the contract to replicate. All bullet points below were read from
`objdiff-core/src/diff/{mod,code,data}.rs` and `objdiff-core/src/obj/`.

### 4.1 Alignment (`diff/code.rs::diff_instructions`)

- **Patience diff** (`similar::capture_diff_slices(Algorithm::Patience, ...)`)
  over the **`opcode: u16` sequence** of each side's `InstructionRef`.
  Opcodes are architecture-scoped ids; equality at the alignment stage is
  opcode-only (relocs do **not** affect alignment).
- The diff ops (Equal/Replace/Delete/Insert) are converted to rows; on a
  `Replace` the **shorter side is padded with empty rows** so both row lists
  are equal length and can be zipped (`(Some,None)`→Delete, `(None,Some)`→Insert).
- `diff_code`: `diff_instructions` → `resolve_branches` on both sides →
  per-row `diff_instruction`.

### 4.2 Per-row classification (`diff/code.rs::diff_instruction`)

```
(Some, None)                 -> Delete        (+100)
(None, Some)                 -> Insert        (+100)
(None, None)                 -> None
l.opcode != r.opcode         -> Replace       (+60), args not compared
opcode equal:
    disasm equal && reloc_eq -> None
    else process args:
        arg count differs    -> Replace       (+60)
        mnemonic differs     -> OpMismatch    (+5)
        per-arg arg_eq:
            Value/Value      -> loose_eq (Signed/Unsigned cross-compare; Opaque string-eq)
            Value/Reloc      -> match iff FunctionRelocDiffs == None (relaxed)
            Reloc/Reloc      -> reloc_eq (§4.4)
            BranchDest/BranchDest -> same branch_to.ins_idx (row indices!)
            BranchDest/Reloc -> match iff relaxed
            else             -> mismatch
        penalty = 1 if left arg is an immediate Value(Signed|Unsigned)
                else 5       (register/reloc/branch arg)
        kind    = ArgMismatch if still None
    if still None but resolved code byte-lengths differ (same disasm, diff encoding,
       e.g. x86)            -> OpMismatch    (+5)
```

Constants: `PENALTY_IMM_DIFF=1`, `PENALTY_REG_DIFF=5`, `PENALTY_REPLACE=60`,
`PENALTY_INSERT_DELETE=100`.

### 4.3 Scoring (`diff/code.rs`)

- `diff_score` = running sum of the penalties above.
- `max_score = left_ops.len() * PENALTY_INSERT_DELETE` (instruction count of the
  **left**/target side).
- `diff_score = min(diff_score, max_score)`.
- `match_percent = 100.0 if max_score == 0 else (1 - diff_score/max_score)*100`.
- Both sides share the same `(diff_score, max_score)` and `match_percent`.

### 4.4 Reloc equality (`reloc_eq` in `diff/code.rs`, `diff/data.rs`)

Config mode `FunctionRelocDiffs` (default `NameAddress`; variants
`None | NameAddress | DataValue | All`):

- `(None,None)` → true; `(None,Some)` → true iff relaxed; `(Some,None)` → false.
- `(Some,Some)`: **reloc flags must be equal** (`RelocationFlags`); relaxed → true.
- Else, `symbol_name_addend_matches = symbol_name_matches(left,right) && addend_eq`.
- Both targets in sections:
  - `section_name_eq`: exact string, full section name (no `$` stripping). `get_section_base_name` is used by `symbol_section` and section combination (Phase 5), not here.
  - `name_ok`:
    - `FunctionRelocDiffs::DataValue` → true (ignore names),
    - both `SymbolFlag::CompilerGenerated` → true,
    - `symbol_name_addend_matches || address_eq(...)` → true.
  - `value_ok`:
    - `FunctionRelocDiffs::NameAddress` → true (ignore values),
    - target not a `SymbolKind::Object` → true (code/function targets),
    - right symbol `size == 0` → true (pool symbols),
    - `ins_data_literals_eq(...)` (target data interpreted as literals) → true.
  - result = `name_ok && value_ok`.
- Extern/absolute targets (`(Some,None)`,`(None,Some)`,`(None,None)`): only
  `symbol_name_addend_matches`.

`address_eq` (pool special case): if `right.size==0 && left.size!=0`, compare
`address + addend`; else compare `address` and `addend` separately.

`symbol_name_matches`: compare `normalized_name` when both present, else exact
`name`. `normalized_name` (`get_normalized_symbol_name` in `obj/read.rs`):
- Metrowerks `prefix@class$NNNNsuffix` → `0000`;
- `prefix$NNNN` → `prefix$0000`; `prefix.NNNN` → `prefix.0000`;
- MSVC `?A0x[8hex]@@` hash → `00000000`.
- **No underscore/sdata/sbss stripping in current main.**

`CompilerGenerated` detection (`is_symbol_name_compiler_generated`):
`@digits`, or `_$E<digits>` / `$LC<digits>` with trailing all-numeric.

### 4.5 Data / BSS (`diff/data.rs`)

- Data symbol: Patience diff over raw bytes; `bytes_match_ratio =
  2*equal/(left_len+right_len)`. If relocs exist in range, **double-count reloc
  bytes**: `match_ratio = (bytes_ratio*left_len + relocs_ratio*total_reloc_bytes)
  / (left_len + total_reloc_bytes)`; `match_percent = ratio*100`. `diff_score`
  is `None`.
- Data relocs matched by **relative offset** within the range; missing left →
  `Delete`, missing right → `Insert`, present → `None`/`Replace` via `reloc_eq`.
- BSS symbol: `100.0` if sizes equal else `50.0` (size-only, no bytes).
- Generic section: byte-weighted average of per-symbol `match_percent`
  (unmatched symbols count 0); `total==0 → 100`.
- Data section: byte ratio over `[0, last_symbol_end)`; **only replaces** the
  generic value when `all_left_relocs_match && data-based > generic`.
- BSS section: Patience diff over `(offset,size)` tuples, `max` with generic.
- Whole-object `match_percent` is **not computed in core**; GUI/CLI aggregate
  (symbol-size-weighted).

### 4.6 Symbol mapping (`diff/mod.rs::matching_symbols`/`find_symbol`)

- Sections matched by **name + kind** (`find_section`/`matching_sections` use full names, no `$` stripping), first-come.
- Symbols matched in two passes `[perfect=false, fuzzy=true]`:
  - ordinary: first unmatched right symbol with `symbol_name_matches &&
    same section_kind && same section_name`;
  - `CompilerGenerated` code/data: run `diff_data_symbol` against every
    unmatched same-section-name CompilerGenerated right symbol; perfect pass
    wants `100.0`, fuzzy pass `>= 50.0` best; BSS: equal size.
- Unmatched → `match_percent: None` (UI shows dimmed).
- `find_similar_code_symbols`: all right code symbols scored against a left
  symbol, sorted by `match_percent` desc (manual pairing UI).

### 4.7 Branches (`arch` scan + `diff/code.rs::resolve_branches`)

- Arch scan sets `branch_dest` for direct branches and for relocs whose target
  symbol is in the same section and lands inside the function range.
- After alignment, `resolve_branches` maps instruction `address → row index`,
  converts `branch_dest` to `branch_to.ins_idx`/`branch_from`, and assigns a
  shared `branch_idx` color for matching branches.
- `process_instruction`: an in-function reloc arg becomes `BranchDest`; external
  calls stay `Reloc`. `BranchDest` equality = same target row index (addresses
  may differ).

### 4.8 Padding / size inference / thunks / switches

- Size inference: `size==0` symbols sized to the gap until the next same-kind
  symbol (or section end); local labels (`.L`, `LAB_`, `switchD_`) skipped;
  MSVC `__unwind$`/`__catch$` records don't terminate a function.
- PPC trims trailing zero words. **Thunks have no special handling** — they
  diff like normal (inferred) symbols.
- Switch tables are **not** read for matching (only PPC pooled relocations).

## 5. Fidelity Notes (our port can't be bit-identical everywhere)

1. **Opcodes**: objdiff's `opcode: u16` is its own per-arch enum. We use
   Capstone `insn.id` as the alignment token (stable within x86-32 mode) —
   alignment is over the same mnemonic-class token space on both sides, so
   behavior matches, but a tiny class-merge difference vs objdiff's enum is
   possible. Documented, acceptable.
2. **Reloc flags**: COFF `.obj` reloc types (LIEF `TYPE`) vs IDA fixups on the
   linked binary are structurally different. Both COFF parsers emit the exact
   relocation type name (`IMAGE_REL_I386_DIR32`, ...) as the class field and
   `reloc_eq` compares them exactly; the legacy IDA markers (`absolute`,
   `relative`, `""`) act as wildcards so linked-binary comparisons stay valid.
   This keeps `reloc_eq` decisions faithful for x86-32.
3. **Addend**: COFF stores no explicit addend for most types — it is implicit
   in the section, so both parsers now read the width-sized little-endian value
   at the reloc offset from the section bytes (FIX 1). IDA fixups expose target
   EAs; `address_eq` bridges the two via symbol base + addend / IDA EA —
   equivalent in practice.
4. **Switch tables**: objdiff compares object files where tables are section
   data on both sides; our base is a live binary where MSVC jump tables live in
   `.rdata` *outside* the function chunk. The existing `switch_ranges`
   strip-and-remap stays, so the `.obj` code aligns with the IDA function
   chunk. This is the one intentional divergence; documented.
5. **Thunks**: current tool skips/scores `[THNK]`; objdiff diffs them normally.
   Decide (see §9) whether to keep skip or adopt objdiff behavior.
